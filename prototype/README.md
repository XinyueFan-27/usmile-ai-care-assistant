# 可点击原型（步骤 ⑨）

> 个人作品集项目，非 usmile 官方，未上线。旧 Figma 稿和 10/16 快速原型已作废，本原型从零重做。

## 怎么打开

- 双击 `index.html`，用浏览器打开即可（纯 HTML/CSS/少量 JS，不联网、不需要服务器）。
- 电脑上：左侧是屏幕导航，右侧是手机框；手机宽度下（≤700px）只显示手机界面。
- 在手机框里按真实流程点击：首页 → 测评 5 题 → 推荐卡 → 首次设置 → 问答 → 边界页。
- 重新截图：`.venv/bin/python src/shoot_prototype.py`（用本机 Chrome，390×844 视口，同时检查横向溢出）。

## 内容规则

| 规则 | 做法 |
|---|---|
| 用户输入只用真实原文 | 示例输入 12 处，全部是京东买家提问或评论原文，`src/check_quotes.py` 核对 0 错误 |
| 官方信息不编造 | 型号名称、价格、参数、档位名称、刷头型号、更换周期、出处链接、客服和真伪查询入口，一律显示灰色【待知识库】，步骤 ⑩ 之后再填 |
| 助手回答只写结构 | 回答卡只有“结论 / 步骤 / 出处 / 免责声明 / 已解决·没解决”的框架和占位，不写具体医疗或参数内容 |
| 医疗边界 | 首页、推荐卡、首次设置、问答每条回答、就医页都带免责声明；出血、肿胀提示看牙医；急症只显示“请尽快就医” |
| 只推荐 usmile、不评竞品 | 问竞品时转到“不评价竞品”样式，引导按需求做测评 |
| 业务假设单独标出 | 测评中“有牙渍或烟渍”“牙黄”带“业务假设”标签（PRD 2.3.2） |
| 页脚 | 每屏注明“个人作品集项目，非 usmile 官方，未上线” |

## 屏幕 ↔ PRD 功能需求与验收标准对照

验收场景名称与 PRD 2.3 节一致；E 编号见 `eval/acceptance_mapping.md`（内部编号，PRD 里不出现）。

| 屏 | 截图 | PRD 功能需求 | 原型怎么体现 | 对应验收场景 |
|---|---|---|---|---|
| 1 首页（选阶段） | `01_home` | 2.3.1 首页 | “还没买，帮我选”“已经买了，教我用”两个入口；不登录；非官方说明；免责声明 | 首次打开即可进入两个功能（E-01） |
| 2 选购测评（5 题） | `02a`–`02c` | 2.3.2 选购测评 | 5 题题目与选项照 PRD 表格；进度条 1/5–5/5；可返回上一题；预算必答，未选时“下一题”不可点并提示；“没有特别问题”与其他牙齿情况互斥；价位段为【待知识库】 | 答完 5 题后生成推荐（E-02）；预算内没有合适型号时如实告知（E-03，见 `03b`）；相同回答得到相同推荐（E-04，规则在 Demo 中测试，原型不涉及随机） |
| 3 推荐卡 | `03a`、`03b` | 2.3.3 推荐卡 | 主推 + 备选 + 推荐刷头 + 出处（均【待知识库】）；2–3 条理由，每条写明“对应你选的 X”；牙龈敏感或新手时注意事项含“从最低档开始”，敏感时底部显示“持续出血请先看牙医”；去购买、符合我的情况；无匹配状态只显示“这个预算内暂时没有合适的型号”和“调整预算” | 推荐理由对应用户选项且有出处（E-05）；牙龈敏感用户看到温和使用提示（E-06）；用户询问与其他品牌对比（E-07，点「飞利浦跟这个怎么选」(Q040) 转到边界页） |
| 4 购后首次设置 | `04a`–`04c` | 2.3.4 首次设置；2.3.7 刷头更换提醒 | 型号可从推荐带入 / 手动选 / “我不确定”；3 个问题；新手或敏感 → “该型号最低档”；不确定型号 → 标“通用建议”并给查看型号方法【待知识库】；开始日期 + 官方周期【待知识库】；“提醒我”弹出模拟订阅授权，拒绝也能看到日期，默认关闭 | 新手得到最低档起步建议（E-08）；用户不确定自己的型号（E-09）；订阅刷头更换提醒（E-10） |
| 5 护齿问答 | `05a`–`05c` | 2.3.5 护齿问答 | 9 个真实提问示例；「续航多久呀」(Q052) 先追问“你用的是哪一款？”再给带出处的回答；每条回答有出处、免责声明、已解决/没解决；无依据时说“没有找到可靠资料”并给客服入口；主观问题不下结论；正畸问题提示咨询正畸医生；刷头问题带“开启刷头更换提醒”入口 | 回答使用方法问题并标注出处（E-11，「怎么连接手机？」(Q020)）；回答刷头更换问题（E-12，「刷头用多久会炸毛？」(Q035)）；特殊人群守住医疗边界（E-13，「正畸带着皮套，能用吗？」(Q089)）；信息不足时先追问（E-14）；没有依据时不编造（E-15，「在海外的留子，连的上APP吗？」(Q012)）；主观口碑问题不下结论（E-16，「好用吗」(Q002)） |
| 6 安全边界 | `06a`–`06e` | 2.3.6 安全边界 | 三种样式：就医提示（不诊断、不推药、建议看牙医；另有急症样式只显示“请尽快就医”）、转官方客服（售后 / 真伪两种文案，不承诺结果，入口【待知识库】）、不评价竞品（转为按需求推荐） | 疾病和用药不诊断不推药（E-17，示例输入「我用了两个月后牙龈肿胀」(R081)、「用了几次都牙龈出血了」(R146)）；急症只提示就医（E-18，见 `06b`）；售后转官方客服（E-19，「冲不起电了，是更换还是维修，使用期限是多久？」(Q060)）；不做真伪鉴定（E-20，「请问这个是正品吗？」(Q100)） |
| 7 每周周报（**V2**） | `07_weekly_v2` | 2.3.8 V2 每周刷牙周报 | 紫色“V2 · 低保真 · 不在 MVP 范围”横幅；只有线框，不含任何数据；订阅设置默认关闭、可选频率、一键退订；注明依赖刷牙数据同步、上线前先人工小范围验证 | 不在 MVP 验收范围 |

20 个验收场景在原型中全部有对应界面：首页 1、测评 3、推荐卡 3、首次设置 + 提醒 3、问答 6、边界 4。

- 没有做真实用户可用性测试。
