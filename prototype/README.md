# 可点击原型（步骤 ⑨）

> 个人作品集项目，非 usmile 官方，未上线。旧 Figma 稿和 10/16 快速原型已作废，本原型从零重做。

## 怎么打开

- 双击 `index.html`，用浏览器打开即可（纯 HTML/CSS/少量 JS，不需要服务器）。首页人物图在线加载，离线时显示浅色底，其他内容不受影响。
- 电脑上：左侧是屏幕导航，右侧是手机框；手机宽度下（≤700px）只显示手机界面。
- 真实流程：首页 → 智能选购（5 题测评 → 推荐卡 → 问 AI 助手 / 买好了）→ 我的牙刷（选型号）→ 型号在 App 适配列表中：引导绑定 → 画像同步；不在列表中或不确定：首次设置 + 刷头提醒 → AI 问答（特定场景弹出安全边界提示）。
- 重新截图：`.venv/bin/python src/shoot_prototype.py`（用本机 Chrome，390×844 视口，同时检查横向溢出）。

## 视觉风格

参照 Melody 提供的 Figma Make 最小 demo。
- **首页顶部按 Figma 原设计还原**：标识栏、“你的专属护齿搭档 / 今天，也要好好爱牙”横幅和人物图（Figma 稿引用的 Unsplash 图片，在线加载）、“AI SMART SERVICE / 我可以帮你 / 7×24 小时在线”、蓝 / 浅绿两张功能卡；两张卡的文字改为“智能选购”“AI 问答”。
- 其余页面借用同一风格：大圆角白卡片、分段进度条 + 字母选项卡、深色主推卡 + “为什么适合你”格子、蓝色用户气泡和圆形发送按钮；顶部保留小程序胶囊。
- 不用 Figma 稿里的示例数据（型号名、匹配度、续航天数等），官方信息仍是【待知识库】。

## 内容规则

| 规则 | 做法 |
|---|---|
| 用户输入只用真实原文 | 示例输入 13 条，全部是京东买家提问或评论原文（首页“热门问题”复用其中 3 条），`src/check_quotes.py` 核对 0 错误。测评“其他，自己填写”的输入框在截图里留空，不编造用户输入 |
| 官方信息不编造 | 型号名称、价格、参数、档位名称、刷头型号、更换周期、出处链接、客服和真伪查询入口，一律显示灰色【待知识库】，步骤 ⑩ 之后再填 |
| 助手回答只写结构 | 回答卡只有“结论 / 步骤 / 出处 / 免责声明 / 已解决·没解决”的框架和占位，不写具体医疗或参数内容 |
| 医疗边界 | 首页、推荐卡、首次设置、问答每条回答、就医弹窗都带免责声明；出血、肿胀提示看牙医；急症只显示“请尽快就医” |
| 安全边界是弹窗 | 不是单独页面：在 AI 问答里遇到就医、售后、真伪、竞品等场景时，由助手弹出对应提示，关闭后回到对话 |
| 界面不显示“智能款 / 基础款” | 用户只选型号；系统按 App 适配列表判断后续路线。原型演示约定：型号 A 在列表中，型号 B 不在列表中（只写在电脑端侧栏和本文件，手机界面不出现） |
| 只推荐 usmile、不评竞品 | 问竞品时弹出“不评价竞品”，引导按需求做测评 |
| 业务假设单独标出 | 测评中“有牙渍或烟渍”“牙黄”带“业务假设”标签（PRD 2.3.2） |
| 页脚 | 每屏注明“个人作品集项目，非 usmile 官方，未上线” |

## 屏幕 ↔ PRD 功能需求与验收标准对照

章节号对应 PRD“二、需求描述”的 2.3 节；验收场景名称与 PRD 一致，E 编号见 `eval/acceptance_mapping.md`（内部编号，PRD 里不出现）。

| 屏 | 截图 | PRD 需求 | 原型怎么体现 | 对应验收场景 |
|---|---|---|---|---|
| 1 首页 | `01_home` | 2.3.1 首页 | “智能选购”“AI 问答”两个功能卡；“热门问题”3 条京东买家提问原文，点击直接进入问答；底部标签栏（首页 / 智能选购 / AI 助手 / 我的牙刷）；不登录；非官方说明；免责声明 | E-01 首次打开即可进入两个功能 |
| 2 智能选购（5 题） | `02a`–`02c` | 2.3.2 选购测评 | 5 题题目与选项照 PRD；第 1 题是 4 个价位段（200 元以下 / 200–400 / 400–800 / 800 元以上，按 10/18 京东官方自营店标价，D39），只能选不能填；第 2–4 题多一个“其他，自己填写”；分段进度条；可返回；预算必答；“没有特别问题”与其他互斥；自己填写的内容不参与规则选型号 | E-02 答完 5 题后生成推荐；E-03 预算内没有合适型号时如实告知（`03b`）；E-04 相同回答得到相同推荐 |
| 3 推荐卡 | `03a`–`03c` | 2.3.3 推荐卡 | 深色主推卡 + 备选 + 刷头 + 出处（【待知识库】）；“为什么适合你”对应用户选项；敏感 / 新手提示“从最低档开始”，敏感时“持续出血请先看牙医”；**“对这款还有疑问？问 AI 助手”**：进入问答后自动发送推荐的型号，助手先问“你想了解什么”（`03c`）；无匹配只提示并给“调整预算” | E-05 推荐理由对应用户选项且有出处；E-06 牙龈敏感用户看到温和使用提示；E-07 用户询问与其他品牌对比（从推荐卡进入问答后问「飞利浦跟这个怎么选」(Q040)，弹出不评价竞品，见 `08e`） |
| 4 我的牙刷：选择型号 | `04_my_toothbrush_pick_model` | 2.3.8 按型号分流 | 只列型号 A / 型号 B（名称【待知识库】）和“我不确定”，界面不出现“智能款 / 基础款”；选好后按 App 适配列表（【待核实】）自动走对应路线 | E-21 分流：在列表中（不显示首次设置和刷头提醒，见 `05`）；E-22 分流：不在列表中（显示首次设置和刷头提醒，见 `06c`） |
| 5 引导绑定笑容加 App | `05_bind_app` | 2.3.9 设置引导 | 显示“你的型号：型号 A”和“这款牙刷可以用笑容加 App 管理”；下载 App（入口【待知识库】）→ “去 App 绑定”（步骤【待知识库】）；“已绑定，去 App 设置” | E-21 |
| 6 画像同步 | `06a`、`06b` | 2.3.10 画像同步（小程序 → App） | 点“去 App 绑定”后出现授权页；只列 4 项（牙齿情况、最想解决的问题、想要的功能、是否新手），**不同步预算**；只同步一次；需单独同意；撤回方式【待核实】；拒绝不影响绑定 | E-24 授权后同步测评画像 |
| 7 首次设置 + 刷头提醒 | `06c`–`06e` | 2.3.4 首次设置；2.3.7 刷头更换提醒（只面向不在 App 列表中的型号） | 顶部显示已选型号，可更换；新手或敏感 → 最低档；不确定型号 → “通用建议”；开始日期 + 官方周期【待知识库】；“提醒我”模拟订阅授权，拒绝也能看到日期，默认关闭 | E-08 新手得到最低档起步建议；E-09 用户不确定自己的型号；E-10 订阅刷头更换提醒；E-22 |
| 8 AI 问答 | `07a`–`07e` | 2.3.5 护齿问答；2.3.9 设置引导；2.3.11 设备数据同步（V2） | 顶部显示“当前型号：…”（不显示款式类别），可更换；「续航多久呀」(Q052) 未选型号时先追问再答；每条回答有出处、免责声明、已解决 / 没解决；无依据不编造；主观问题不下结论。型号在 App 列表中时：问设备设置 → 简要说明 + “去笑容加 App 设置”（`07d`）；V2 问「轻柔模式能刷干净吗」(Q117) → 红色虚线框标注“模拟设备数据，仅作演示，非真实用户”（`07e`） | E-11（「怎么连接手机？」(Q020)）；E-12（「刷头用多久会炸毛？」(Q035)）；E-13（「正畸带着皮套，能用吗？」(Q089)）；E-14 信息不足先追问；E-15（「在海外的留子，连的上APP吗？」(Q012)）；E-16（「好用吗」(Q002)）；E-23（「默认模式是什么？能切换默认模式，下一次刷一起动还是想要的模式么？」(Q088)）；E-25（V2） |
| 安全边界弹窗 | `08a`–`08e` | 2.3.6 安全边界 | 在问答中触发后弹出，不是单独页面：就医提示（不诊断、不推药；另有急症样式只显示“请尽快就医”）、转官方客服（售后 / 真伪，入口【待知识库】）、不评价竞品（转为按需求推荐）；“知道了”关闭后回到对话 | E-17（「用了几次都牙龈出血了」(R146)、「我用了两个月后牙龈肿胀」(R081)）；E-18 急症（`08b`）；E-19（「冲不起电了，是更换还是维修，使用期限是多久？」(Q060)）；E-20（「请问这个是正品吗？」(Q100)）；E-07（`08e`） |

E-01 – E-25 共 25 个验收场景在原型中都有对应界面。2.3.12 新手适应期（V2）未画屏。

**与 PRD 措辞的差异（待 PRD 同步）**：① 首页两个入口改为“智能选购”“AI 问答”，已购用户从底部“我的牙刷”或右上角进入选型号（PRD 2.3.1 写的是“帮我选 / 教我用”）；② 安全边界改为问答中的弹窗（PRD 2.3.6 写的是“显示安全边界页”）；③ 界面不显示“智能款 / 基础款”。

**模拟设备数据（D35）**：只出现在 `07e`（2.3.11，V2），只写“较多（模拟）”这类定性摘要，更新时间写“模拟”，并醒目标注“模拟设备数据，仅作演示，非真实用户”。

## 局限

- 原型只演示界面结构和流程，所有官方信息待步骤 ⑩ 知识库补齐；问答输入框只响应示例问题。
- 小程序订阅消息授权是模拟弹窗，真实规则【待核实】（PRD 14.1）。
- 没有做真实用户可用性测试。
