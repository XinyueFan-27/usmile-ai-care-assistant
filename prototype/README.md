# 可点击原型（步骤 ⑨）

> 个人作品集项目，非 usmile 官方，未上线。旧 Figma 稿和 10/16 快速原型已作废，本原型从零重做。

## 怎么打开

- 双击 `index.html`，用浏览器打开即可（纯 HTML/CSS/少量 JS，不联网、不需要服务器）。
- 电脑上：左侧是屏幕导航，右侧是手机框；手机宽度下（≤700px）只显示手机界面。
- 在手机框里按真实流程点击：首页 → 选择你的情况 → 还没买（测评 → 推荐卡）/ 智能款（引导绑定 → 画像同步）/ 基础款（首次设置 + 刷头提醒）→ 问答 → 边界页。
- 重新截图：`.venv/bin/python src/shoot_prototype.py`（用本机 Chrome，390×844 视口，同时检查横向溢出）。

## 内容规则

| 规则 | 做法 |
|---|---|
| 用户输入只用真实原文 | 示例输入 12 处，全部是京东买家提问或评论原文，`src/check_quotes.py` 核对 0 错误 |
| 官方信息不编造 | 型号名称、价格、参数、档位名称、刷头型号、更换周期、出处链接、客服和真伪查询入口，一律显示灰色【待知识库】，步骤 ⑩ 之后再填 |
| 助手回答只写结构 | 回答卡只有“结论 / 步骤 / 出处 / 免责声明 / 已解决·没解决”的框架和占位，不写具体医疗或参数内容 |
| 医疗边界 | 首页、推荐卡、首次设置、问答每条回答、就医页都带免责声明；出血、肿胀提示看牙医；急症只显示“请尽快就医” |
| 只推荐 usmile、不评竞品 | 问竞品时转到“不评价竞品”样式，引导按需求做测评 |
| 业务假设单独标出 | 测评中“有牙渍或烟渍”“牙黄”带“业务假设”标签（PRD 2.3.2） |
| 页脚 | 每屏注明“个人作品集项目，非 usmile 官方，未上线” |

## 屏幕 ↔ PRD 功能需求与验收标准对照

按 PRD“需求描述”一章的需求名对应（章节编号以 PRD 当前版本为准）；验收场景名称与 PRD 一致，E 编号见 `eval/acceptance_mapping.md`（内部编号，PRD 里不出现）。

小程序与笑容加 App 分工：小程序是所有 usmile 用户的轻入口（售前测评、问答、基础款设置）；智能款的设备设置、刷牙报告、刷头记录与提醒交给 App，小程序不重复做。

| 屏 | 截图 | PRD 需求 | 原型怎么体现 | 对应验收场景 |
|---|---|---|---|---|
| 1 首页 | `01_home` | 首页 | “开始：选择你的情况”“直接提问”两个入口；不登录；非官方说明；免责声明 | 首次打开即可进入两个功能（E-01） |
| 2 选择你的情况 | `02_route` | **按型号分流**（新增） | 三条路线：还没买 → 测评；已买智能款（支持笑容加 App）→ 引导绑定；已买基础款（不连 App，如 P10）→ 首次设置。适配机型、基础款机型、查看型号方法均为【待知识库】；问答对三条路线都开放 | PRD 新增场景（待 PRD 补齐后对应） |
| 3 选购测评（5 题） | `03a`–`03c` | 选购测评 | 5 题题目与选项照 PRD；进度条；可返回；预算必答；“没有特别问题”与其他互斥；价位段【待知识库】 | 答完 5 题后生成推荐（E-02）；预算内没有合适型号时如实告知（E-03，见 `04b`）；相同回答得到相同推荐（E-04） |
| 4 推荐卡 | `04a`、`04b` | 推荐卡 | 主推 + 备选 + 刷头 + 出处（【待知识库】）；理由对应用户选项；敏感 / 新手提示“从最低档开始”，敏感时“持续出血请先看牙医”；无匹配时只提示并给“调整预算”；“买好了 → 按型号继续”回到分流屏 | 推荐理由对应用户选项且有出处（E-05）；牙龈敏感用户看到温和使用提示（E-06）；用户询问与其他品牌对比（E-07，「飞利浦跟这个怎么选」(Q040)） |
| 5 引导绑定笑容加 App | `05_bind_app` | **设置引导**（新增） | 智能款用户：说明设备设置和报告都在 App 里；三步：下载 App（入口【待知识库】）→ 在 App 里绑定（步骤【待知识库】）→ 可选同步测评结果 | PRD 新增场景（待 PRD 补齐后对应） |
| 6 画像同步 | `06a`、`06b` | **画像同步**（新增） | 列出将同步的测评答案（用户自己的选项）；授权说明：只同步这一次、牙齿情况需单独同意、撤回方式【待核实】、不同意不影响使用；“同意同步 / 暂不同步”；没做测评时提示无可同步内容 | PRD 新增场景（待 PRD 补齐后对应） |
| 7 首次设置 + 刷头提醒（基础款） | `07a`–`07c` | 首次设置；刷头更换提醒（只面向基础款） | 只在基础款路径出现；型号为基础款【待知识库】或“我不确定”；新手或敏感 → 最低档；不确定 → “通用建议”；开始日期 + 官方周期【待知识库】；“提醒我”模拟订阅授权，拒绝也能看到日期，默认关闭 | 新手得到最低档起步建议（E-08）；用户不确定自己的型号（E-09）；订阅刷头更换提醒（E-10） |
| 8 护齿问答 | `08a`–`08d` | 护齿问答；**设置引导**（问答内） | 顶部“演示身份”切换未购 / 智能款 / 基础款。智能款问「怎么连接手机？」(Q020) → 先简要说明，再给“去笑容加 App 设置”；问刷头 → 指向 App 的刷头记录；基础款问刷头 → “开启刷头更换提醒”。「续航多久呀」(Q052) 先追问型号再答；每条回答有出处、免责声明、已解决 / 没解决；无依据不编造；主观问题不下结论 | 使用方法问题标注出处（E-11）；刷头更换问题（E-12，「刷头用多久会炸毛？」(Q035)）；特殊人群守住医疗边界（E-13，「正畸带着皮套，能用吗？」(Q089)）；信息不足先追问（E-14）；没有依据不编造（E-15，「在海外的留子，连的上APP吗？」(Q012)）；主观口碑不下结论（E-16，「好用吗」(Q002)） |
| 9 安全边界 | `09a`–`09e` | 安全边界 | 就医提示（不诊断、不推药，另有急症样式只显示“请尽快就医”）、转官方客服（售后 / 真伪，入口【待知识库】）、不评价竞品（转为按需求推荐） | 疾病和用药不诊断不推药（E-17，「我用了两个月后牙龈肿胀」(R081)、「用了几次都牙龈出血了」(R146)）；急症只提示就医（E-18）；售后转官方客服（E-19，「冲不起电了，是更换还是维修，使用期限是多久？」(Q060)）；不做真伪鉴定（E-20，「请问这个是正品吗？」(Q100)） |

原 20 个验收场景都有对应界面；按型号分流、画像同步、设置引导 3 个新增需求的验收场景由 PRD 补写，补齐后再在本表填上编号。周报屏已删除（App 已有日 / 周 / 月报告）。

**模拟设备数据**：本版原型没有演示 App → 小程序的设备数据（那是 V2）。如以后加入，页面必须醒目标注“模拟设备数据，仅作演示，非真实用户”。

## 局限

- 原型只演示界面结构和流程，所有官方信息待步骤 ⑩ 知识库补齐；问答输入框只响应示例问题。
- 小程序订阅消息授权是模拟弹窗，真实规则【待核实】（PRD 14.1）。
- 没有做真实用户可用性测试。
